# `strip-listing.py`

Remove z80dasm `-t` address/byte/ASCII listing tails from assembly files while
preserving semantic comments embedded in those tails. Use it on generated
disassembly before folding code into committed source.

The helper edits each supplied file in place. It does not use
`workbench.cfg`, and paths are resolved from the current directory.

## Prerequisites

- Python 3.
- One or more writable text assembly files generated by z80dasm with `-t`.

## Syntax

```sh
tools/workbench/msx/strip-listing.py FILE.asm [MORE.asm ...]
```

There are no options. The script does not implement `--help`; any token is
treated as a filename. If no filenames are supplied, it exits successfully
without output.

## Clean generated assembly

```sh
cp generated/bank04.raw.asm /tmp/bank04.clean.asm
tools/workbench/msx/strip-listing.py /tmp/bank04.clean.asm
```

For each recognized line, the helper removes a final listing field shaped
like:

```text
;<four-hex-digit-address><tab><space-separated hex bytes><tab><tail>
```

If the tail starts with `;` and contains at least one word longer than one
character, it is treated as a semantic comment and retained. Retained comments
are aligned to visual column 32 when possible. z80dasm ASCII renderings such
as `. .`, `! . L`, or `>` are dropped with the address and byte listing.

Earlier comments in the code field, including z80dasm diagnostics such as
`illegal sequence`, remain intact.

After each file, the command prints a summary:

```text
/tmp/bank04.clean.asm: dropped 812 byte-listings, kept 7 semantic comments
```

Lines that do not match the expected z80dasm listing shape pass through
unchanged and are not counted.

## Effects and gotchas

- Files are overwritten directly; no backup or temporary output is created.
  Copy irreplaceable input first.
- The recognizer requires a four-digit hexadecimal address and tab-delimited
  listing structure. Output from another disassembler or a changed z80dasm
  format may remain untouched.
- Semantic-comment detection is structural, not linguistic. A real comment
  that does not begin with a second semicolon, or contains only one-character
  tokens, is dropped as listing ASCII.
- A listing ASCII tail beginning with `;` and containing a multi-character
  token would be retained even if it is not meaningful.
- Files are read and written using Python's default text encoding. Invalid
  encoding, missing files, or permission failures produce a Python exception.
- Run `make verify` after folding cleaned output. Removing listing comments
  should not affect bytes, but surrounding manual edits can.
